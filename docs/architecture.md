# Architecture — what each directory and package of the repo is

The reference map of the repo: read it before working in an area you do not know yet, or before
touching packaging and deployment. The root `AGENTS.md` keeps a one-line map and the rules every
task needs. A path written `docs/…` beside a package or an app means that zone's own `docs/`, as
everywhere in this repo ([lints.md](lints.md), which also holds the repo's own checks).

## The apps and the engine

`studio` holds the music/stage apps. Every app runs on the musician's device: k7 has no hosted
origin, so the audio side is one machine, the device's own, which is why this overview lives in the root `docs/` and not inside any one app. Two processes run on the
musician's machine — `engine/k7-runtime` and `engine/k7-supervisor` — either on their own, as the
command-line engine (`k7-supervisor --config <file>`), or inside an app: the tray (`apps/k7-tray`), through the k7 backend it runs, or the phone (`engine/k7-android`, `engine/k7-ios`). An engine image of their own is still built (`docs/server-engine.md`):

| dir | language | what it is |
|---|---|---|
| `engine/k7-runtime` | C++ | The audio engine. Receives a compiled `ProjectDoc` over WebSocket, diffs it, plays audio, pushes transport and meter state back. **Never parses song files.** |
| `engine/k7-supervisor` | C++ | The engine machine's **supervisor**: starts, adopts and watches the engine, keeps it listed at the studios it is connected to, holds the tunnel its own backend reaches the machine through, and runs the work the backend asks of the machine — a stem cut, a set list brought down, a file for the player (`docs/supervisor.md`). |
| `engine/scripts` | Node | The scripts that build the engine and the supervisor and package what ships: the command-line engine's archive, and the tray's release files around the same binaries (`engine/scripts/docs/buildEngine.md`). |
| `engine/k7-android` | Kotlin (Gradle) | The engine on a PHONE: the same engine as a library the app loads, since JUCE's Android audio reaches Java, and the same supervisor as a program it runs, driven over stdio as k7's backend drives it under the tray. STANDALONE like the tray: it also runs k7's backend, bundled, under Termux's node, so a phone opens its own studio. Foreground only (`engine/k7-runtime/docs/android.md`). |
| `engine/k7-ios` | Swift (Xcode) | The same on an IPHONE, part for part (and on an Apple-silicon Mac, as the iPad app: `ios.md`), with what iOS forbids answered: no app may run a program or start a process, so the engine AND the supervisor are frameworks run on threads of the app, node is NodeMobile, the backend a worker thread of it, with k7's Rust front in the same process. The shell page and the page scripts are Android's own. Staged by `scripts/stage.mjs` before Xcode builds it (`engine/k7-runtime/docs/ios.md`). |
| `apps/k7` | TypeScript | The text-first DAW, and the only app that opens a project: `frontend` (React/Vite) + `backend` (Express — the session it reads and the account's preferences, behind the Rust front that answers the file service, the engine registry and the rest of the routes; one process, `apps/k7/backend/src/server.ts`). Owns the timeline; shares the chains view. **Modules and chains are authored here**, against a project where the plugin a module names is actually LOADED, and written into a library folder of the device — a library is a plain folder, seeded from the `k7-core/` the app bundles and changed by an app update (`packages/song/docs/sharedFolders.md`). A project is created from one of five **archetypes**: three named after the surface they open on — `arrangement` (a timeline), `mix` (two decks and a crossfade — `packages/song/docs/setProject.md`), `video` (a timeline and a viewport) — and the two `live` ones, named after what they ARE: a rig you play THROUGH, with nothing arranged and no lane of any kind — an input, a fader, the master run, and in `live-video` a webcam feeding RENDER plus the one viewport a picture cannot do without (`packages/song/docs/liveProject.md`) — and a song holds **sound and picture** alike: video lanes on the same timeline, whose ruler reads bars or seconds, and a `viewport` surface that composites them (`docs/picture.md`). What it draws beyond its panes, it draws because the project DECLARED it, in `surfaces/` (`docs/surfaces.md`). It opens the account's **playlists** as well — `_playlists/` at the workspace root, listing audio files of the workspace, a record each (`frontend/docs/playlists.md`). A `turntables` surface NAMES one, and that is what the DJ desk's browser lists and what the machine pre-fetches before a gig. Beside those, `_references/` — the finished mixes you listen AGAINST, uploaded there and played by the BROWSER so a reference sounds over a live rig or a running arrangement without going near the engine (`frontend/docs/references.md`). It owns the level above a project too: its **home page** — the ORIGIN with no project in the address — lists the device's workspaces, the projects inside them and the libraries (`frontend/docs/projects.md`) — and its left sidebar carries the origin's USER MENU (`packages/ui-user-menu/docs/userMenu.md`). It runs on the device only, opened at the loopback address of its own front (the tray's `127.0.0.1:18789`) or in the app's own view; `docs.k7.rocks` serves its documentation alone (`frontend/docs/docsSite.md`), and a project is addressed `/@local/<workspace>/<project>` — a folder on the machine that holds it, with `@banc` (the bench, a live rig seeded with a library chain) the only other openable address — plus `/external`, the menu of surfaces a second device drives, kept until the app's second-device rework (`frontend/docs/external.md`). Opened ON one WORKSPACE otherwise, by an address rather than a picker — see `packages/project-shell/docs/launch.md`. A workspace is one folder holding SEVERAL projects: the editor's tree is the whole of it and a ▶ on a project row is what hands that one to the engine (`apps/k7/backend-rs/docs/file-projects.md`). It is a git repository only once connected: a folder on the device that git moves between devices (`apps/k7/backend-rs/docs/files/git.md`), whose history between two commits is the capture's own log (`apps/k7/backend-rs/docs/files/history.md`). |
| `apps/k7` — the engine registry | Rust (routes) | The Rust front holds the engine registry (`apps/k7/backend-rs/docs/engine.md`) and the file hub over the device's WORKSPACES (`apps/k7/backend-rs/docs/files.md`), one file service for the one local account. A remote engine is not an app feature: the registry and tunnel code stay for the app's second-device rework (`docs/inventaire.md`). |
| `apps/k7/backend-rs` | Rust | k7's backend in Rust (`docs/rust-backend-plan.md`): `k7-front` listens where the backend listens, answers the file service, the engine registry and the last routes, and hands the Express backend what remains the real peer under a shared secret (`apps/k7/backend-rs/docs/front.md`); `k7-auth` reads and mints the session cookie byte for byte as `@studio/oidc` does (`apps/k7/backend-rs/docs/sessions.md`); `k7_front::embedded` runs the front inside a host's process — the tray links it, the phones reach it through `k7-embed`'s C library (`apps/k7/backend-rs/docs/embed.md`). `k7-js` reproduces the JavaScript number formats a file holds, natively (`apps/k7/backend-rs/docs/parity.md`); `k7-mediatek` is the media core: decode, analysis, envelopes, sidecars, transcodes and the picture's copies. |
| `apps/k7-tray` | Rust (Tauri) | **k7 on a Windows or Linux computer** (a Mac runs the iOS app, Designed for iPad): a windowless Tauri app in the system tray that starts one process, k7's backend bundle under a pinned node, on `http://127.0.0.1:18789` (the port in `apps/k7/backend/standalone.json`, the table the phone uses too). Its Rust front answers the account's files itself and runs the machine's supervisor over stdio, on `~/.k7` and 8765, the same engine the command-line one would be (`apps/k7/backend-rs/docs/local.md`). The person opens k7 in their own browser at that address and can install it as an app; everything it needs is on the machine, so it works offline. The tray draws one status line the backend words and opens k7; it computes no policy. Built on macOS only for the developer's dev session. Built locally, and kept current from `k7.rocks/app_downloads/tray` by tauri-plugin-updater (`apps/k7-tray/docs/tray.md`). The engine is the machine's own. |
## The shared packages

`packages/` is **studio's own shared tier**. All are `@studio/*` and are consumed
as **raw TypeScript source**: no build step, imported through `package.json`
`exports` subpaths, so a bare deep import fails on purpose.

| group | packages |
|---|---|
| the song | `k7-wasm` (the browser's one WebAssembly module: Rust behind a C ABI carrying JSON, the curves and the timecode of `song-schema` first; `packages/song-schema/docs/wasmBoundary.md`), `k7x` (the TEXT every workspace file is written in: Strudel-looking, parsed and never evaluated, edited value by value so every other byte stays — `docs/language.md`, and the plan `docs/k7x-plan.md` at the root), `song-schema` (the FILE FORMAT and the value vocabulary around it — one zod schema and one reader/writer per kind of workspace file, plus `timecode`, `moduleTypes`, `playlist`, `stems`… Nothing in it touches `node:fs`, which is the whole point: **this is the half a browser may import**, and k7's frontend, `ui-editor`, `ui-module-builder`, `k7-plugins` (the desk) and `project-shell` depend on it INSTEAD of on `song`), `packages/song/rust` (the compiler's Rust crate `song`, linked by the backend and built for the browser: the `Source` it reads through, its cache and the file readers so far; `packages/song/docs/rustCompiler.md`), `song-edit` (CHANGING a project rather than compiling one — params, assets, events, material, time; the implementation is the Rust crate `packages/song-edit/rust`, run over WebAssembly in the verbs' Worker and over `__host.edit` in QuickJS, and the TypeScript is stubs and callback glue — `packages/k7-wasm/docs/edit.md`; every write goes through a k7x document that changes the value and nothing else, so a knob drag stays a one-line diff), `song` (folder of k7x files → `ProjectDoc` + `GraphDoc` — the compile, the loader and every disk walk, and only READING; a project is one of three SHAPES, `docs/setProject.md`; it also owns the WORKSPACE's shape around a project — the shared folders, the account's libraries and their third family `assemblies/`, and the `assemblies/` a project draws its nodes as BOXES with, `docs/assemblies.md`, and `_playlists/`, `docs/playlists.md`), `song-video` (the SAME folder → `VideoProjectDoc` for its picture — the video document model, the lane and chain compile, the shaders; `packages/song-video/docs/picture.md`. Split out because a song's sound compiles without any of it; what stays in `song` is `videoOutputs.ts`, which edits the GRAPH rather than the picture, and `isVideoProject`, a folder probe `surfaces.ts` needs — the two edges that would otherwise make this a cycle), `song-strudel` (the Strudel side of a pattern lane — the hap → event mapping and the API the ENGINE runs, bundled into `engine/k7-runtime` and tested here under Node; nothing imports it at run time, since the engine plays every pattern lane, `engine/k7-runtime/docs/patternPlugin.md`), `commands` (one verb list for every surface — the dispatch and the document edits), `audio-probe` (MEASURING decoded audio: the trim gate and the envelope + beat grid. No `node:`, so a BROWSER may have it — k7's clip panel needs no node package for 69 lines of arithmetic), `audio-analysis` (the `{file}.cache` sidecar — a peak/RMS envelope, three colour bands, onsets, a tempo — and a file's true peak, measured from one decode: the engine's `--decode` where the machine has an engine, the Rust decoder built to WebAssembly where it has none, as in k7's backend, and ffmpeg only for a format that one cannot open; the worker pool both services analyse on; and the same module RE-ENCODES — Opus in WebM, FLAC, WAV — for a stream copy of a FLAC, a render's stems, so no audio path of the bundled backend needs ffmpeg; `docs/analysis.md`, `docs/transcode.md`), `take-render` (audio a song PRODUCES: filing a take, rendering a mixdown, reading a wav's length), `video-prep` (a video made fit for the PICTURE: probed with ffprobe, then given an optimized copy a browser decodes or a proxy it previews, made with ffmpeg — `packages/song-video/docs/media.md`), `ffmpeg` (every ffmpeg and ffprobe a Node process here runs — the binary, `FFMPEG_BIN` / `FFPROBE_BIN`, the one `NoFfmpegError`, and every input opened under `-protocol_whitelist file,pipe`, since what they read is uploaded — `packages/ffmpeg/docs/ffmpeg.md`), `audio-passes` (the offline passes a chain runs — process, peak, cold; the RUNNING is handed in by the host, `docs/processChain.md`), `translator` (`.dawproject` import), `dsp` (write a module's DSP in JS) |
| the engine | `engine-protocol` (the wire, mirrored in C++), `engine-client` (Node), `engine-browser` (browser + React store; its `access` subpath is the ONE way an app reaches an engine — routes, probe, policy, lease, bound to that service's prefix), `engine-registry` (the internal seam's client and gate, through which the TypeScript reaches the Rust front's registry and tunnel hub, `docs/internalSeam.md`), `engine-tunnel` (the way IN: the supervisor dials the server that lists it — the hub is the Rust front's, the machine's agent in `engine/k7-supervisor` with `agent.ts` its TypeScript reference — the server reaches the engine through that socket however far apart they are, a server-owned project plays from a local copy, and a browser gets a WebRTC path straight to the engine's machine — `docs/tunnel.md`, `docs/rtc.md`) |
| the disk | (every file operation is the Rust front's, `apps/k7/backend-rs/docs/service.md`: k7's Express backend has none, and an engine's machine has none: an engine is shared by the accounts that play on it, and what the server needs of that machine — a stem cut, a set list copied, a file brought down — is a job its supervisor runs over the tunnel, `packages/engine-tunnel/docs/jobs.md`; the hub that keeps each account's workspaces under `$STUDIO_FILES_ROOT` is the front's too, `apps/k7/backend-rs/docs/files.md`), `stem-separation` (the seam a stem cut is handed through to the engine's machine, and the id that keys a job by its work; the cut itself runs in `engine/k7-supervisor`; `docs/stemSplit.md`), `user-prefs` |

| the types | `web-protocol`, `graph-model` (split out so drawing a graph doesn't drag in auth), `http-client` (the browser's side of a call to a studio service: a refusal's sentence and status, a time budget, an upload that reports its progress — k7's editor and home page share it, `docs/httpClient.md`) |

| the app kit | `ui` (the design-system components and the one icon set), `i18n` (the Paraglide wrapper and its Vite plugin), `http` (Express helpers), `oidc` (the sign-in and the `studio.sid` session; `apps/k7/backend-rs/docs/sessions.md`), `env` (a service's section of `env.yaml`), `vite-config` (the shared Vite preset), `tsconfig` (the TypeScript bases) |

They are named `@studio/*` rather than `@k7-core/*` because k7 is only one of
their consumers: apps in other repositories consume four of them. Those four — `web-protocol`,
`engine-protocol`, `engine-browser` and `project-shell` — are the only ones PUBLISHED, by version and
still as raw TypeScript (`docs/publishing.md`); every other package stays private to this tree.

## Production

**The apps run on devices.** k7 is the tray (Windows, Linux), the Android app, and the iOS app (a Mac runs it as the iPad app): each carries its own front, file service, engine registry and engine, and moves workspaces by git (and iCloud keys on Apple devices). There is no hosted app, no account on a server and no server to pair with.

**The server image only publishes.** `docker/docker-compose.yml` still runs ONE image of k7 (the Express backend and k7's Rust front), and it serves `k7.rocks` (the root site, `/app_downloads` and the update feeds the tray and the Android app read, `docs/app-downloads.md`) and `docs.k7.rocks` (the documentation), nothing else; `docs/images.md` keeps what the image holds and why. The command-line engine's image (`engine/docker/Dockerfile`, `docs/server-engine.md`) and the Raspberry Pi's (`docs/pi-engine.md`) are built as before. `docs/versioning.md` is the page.

## `k7-core/`

`k7-core/` is a plain folder of this repository: the `@k7-core` modules library, the SEED every app bundles and copies a library folder from. It is here so
a module and the code it relies on change together, in one commit. It is a PUBLISHED version: its
`library.k7x` says which, and **a change to its content raises that `version`** in the same commit —
a version already installed is never rewritten, so an unchanged number reaches no machine
(`docs/library-versions-plan.md`). Its binaries (IRs, amp models,
presets) are ordinary tracked files; a path in it stays short, since a Windows checkout refuses one
past 260 characters.
