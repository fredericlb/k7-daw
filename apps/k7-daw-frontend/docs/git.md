# A workspace under git: the screens

The home page connects a workspace to a git remote or clones one, and a bar over the workspace shows where it stands
against the remote. The routes are `apps/k7-daw-backend/docs/files/git.md`, the repository and the merge are
`apps/k7-daw-backend/docs/git.md`; this page covers what the screens decided. The code is `src/git/`.

## Choices

| choice | why |
|---|---|
| the bar branches on the route's `state` alone, through one function (`barView`) | the routes own the rules of what may go where; a screen that rebuilt them from `ahead`, `behind` and `changed` would drift |
| Push, Pull and Commit are the person's acts: nothing is pushed, pulled or committed by itself | a take or a song is a unit of work the person names; the fetch only looks |
| Commit & Push is one act, shown as a Commit row and a Push row inside the dialog, which closes on a toast when the push ends | a commit nobody pushes is a step the person had to remember; the rows say where an act stopped, and a finished act has nothing left to read |
| a push the remote refuses as `behind` is the dialog's own state, "Pull first", with the commit kept; any other failure is the failed step with Try again, which resumes at that step | the refusal is the next step, not an error, and a failed push must never commit twice |
| with nothing to commit and commits waiting, Commit & Push only pushes; a workspace with no remote only commits | the act does what the workspace can do, so a pull that was merged can still be sent |
| Pull over uncommitted changes reads "Commit first" and is dimmed | the sentence says the next step, and the server's refusal (`uncommitted`) is the same sentence if a stale bar lets a click through |
| Abort asks inside the Conflict screen, as a nested `dialog "Abort the merge?"`, not as a popin | the screen is a full-screen layer above every popin, which would be drawn under it |
| the remote dialog has no HTTPS / SSH choice | k7 is ssh only: a choice with a refused option would only be a trap |
| the command editor is a full-screen editor; its Save writes the whole draft, and a key taken from another command is said under the filter row | a shortcut saved one at a time would half-apply when the person leaves |
| a clean workspace over an empty remote says "Nothing pushed to {repo} yet" with the next step, instead of "Up to date"; a device with changes or commits keeps Commit & Push | an empty clone must never read as a sync that lost the projects |
| a merge waiting shows only its own button: no Commit, Push or Pull | a commit during a merge would be a second history |
| a pull that diverged opens the merge screen at once | the person was waiting for the answer to the pull |
| the Conflict screen is a full screen over the project (a region, no dialog): a list of conflicts (marked "To choose" until picked) beside the open conflict's two sides and its choices: Keep mine, Keep theirs, Keep both only where the route says, keep or remove for a file one side removed; Previous and Next walk the list | "both" has a meaning only for a keyed list item, or for a binary kept beside under a free name, and the screen never offers what the merge would refuse |
| "Mine for all" and "Theirs for all" skip binaries and removed files | those are the choices a person should look at |
| the choices are sent once, on Finish merge, and Finish is allowed when every conflict has one | nothing moves in the workspace before the person is done; Abort leaves it as it was |
| the editors are read-only while a merge waits, through the shell's write gate and `locked` | the file service answers 423 `merge-pending` to the same writes; the gate says it before the request leaves, and the engine plays on |
| a failed state read keeps the last state; only a missing route (404, 501) clears it | a blip must never unlock the editors of a merge |
| the home page asks each workspace's state every 15 s to refuse its own writes while a merge waits (`useMergingWorkspaces`) | the home page has no bar of its own to keep the state |
| a commit takes the whole tree: the dialog lists the changed files with their sizes and marks large files, it does not select | what is committed is what the person sees, and a partial commit would leave a tree no one has tested |
| a file the status flags `tooLarge` (over 2 GB) is left out of the commit, and a line names it with its size; the dialog sends it as the commit's `exclude` | the host would refuse it, the person's file stays where it is, and the next commit leaves it out again until it is shrunk or removed |
| the state's `changed` and the dialog's "nothing to commit" ignore a `tooLarge` file | a file the commit cannot take must not look like a change waiting |
| a commit asks for a name and an email when the device has none, and keeps them (settings, General) | git needs an author; it is per device because two machines of one person may sign differently |
| the dialog has an address and no sign-in field: no token, no password, no user name, no pasted key | k7 is ssh only; the address carries the user (`git@host:…`) and the device's own key signs in |
| an `https://`, `http://` or `git://` address is said at once ("k7 syncs over SSH only") and cannot be sent; any other address goes to the route, whose `ssh-only` answer is the same sentence | the page names the way on from the first keystroke, and the route stays the one judge of what is an ssh address (the e2e bed's `file://` seam passes) |
| Sign in with GitHub is in Settings → Services only (`settings.md`); Connect and Clone never sign in | a sign-in inside the dialog would chain a second code for `repo` behind the first, which reads as a hang once GitHub has said "success" |
| Connect and Clone open on GitHub's repository picker, with "Another host…" beside it, only when the device is signed in with `repo` (`canPick`); otherwise, or where the path is off, the dialog is the plain ssh one; typing an address is choosing the other way | the GitHub path is an addition, never a requirement: a person with a GitHub account rarely wants the form, and one with a self-hosted remote must never lose it |
| the device flow, not a redirect: a code to type on github.com, polled while the screen is open and the page visible | no server, no client secret and no callback address to register, which suits a device app and a webview that cannot receive a redirect |
| the sign-in asks for the person, the key and `repo` in one code; the picker never asks a permission, and a `scope` refusal points to Settings → Services | the sign-in exists for the picker, so `repo` is needed the moment it ends; one code is one step for the person |
| Settings → Services and Connect/Clone read the accounts, and that read makes the device upload its own key to each signed-in account the first time it sees it; the page does nothing for it | each device uploads the key it signs in with, because a sign-in synced through iCloud says nothing of which key the host holds, and a Mac that adopted the Apple devices' shared key has a new one |
| the token never reaches the page; on Apple devices it is an iCloud Keychain item, elsewhere it stays on the device; git still uses the device's ssh key | the token only calls GitHub's REST API (the key upload, the list, the creation); signing in once for all of a person's Apple devices is the user's choice (`apps/k7-daw-backend/docs/git.md`, "Credentials") |
| the picker lists the account's repositories most recently pushed first, the `k7-workspace` topic under its own heading, a filter, and a private badge and a pushed-ago on each row | a workspace is a repository the person made for k7, and the account may hold hundreds of others |
| "New repository" (Connect only) takes the workspace's name, private by default, and marks the repository with the topic; connecting an existing repository adds the topic too, silently on failure | the topic is what puts a repository first in the picker on the person's other devices; a repository the person cannot administer is still connected |
| Clone's picker fills the address and the name and leaves the person to press Clone | the name is the folder, checked as any workspace's is |
| Sign out removes the token only, and Settings says the key stays; where the account's `synced` is true, the note says the sign-out reaches the person's other Apple devices too | the key is this device's git access and other workspaces may use it; GitHub's own page removes it; a synced item is one item, so its removal is everywhere |
| a Forgejo server is added in Settings → Services by its address: a check reads the version, LFS and whether ROOT_URL answers, then Add server, with nothing registered; the two redirects to register (each with Copy), the one-line way to register them and a Client ID field sit behind a disclosure for a server whose admin turned the built-in clients off, as do the ssh host and port behind theirs | the sign-in uses Forgejo's built-in client (`apps/k7-daw-backend/docs/files/git.md`), which every server has unless its admin turned it off; LFS off and an unanswering ROOT_URL are said, not refused, since the rest still works |
| a server's sign-in is polled every 1.5 s, including while this page is hidden; each end (done, refused, failed, expired) is one sentence and a Try again | the sign-in happens outside the page, which is hidden or covered while it runs |
| the way out and back is chosen per host by `forgeOpener.ts`, from the markers the shells set (`k7Ios`, `k7Android`): a plain browser and the desktop app keep a button that opens the authorize address in a new tab, returning to the loopback callback; the Android app keeps that button and returns through `rocks.k7.daw://callback`; the iOS app starts with the same scheme and opens iOS's web sheet through the bridge (`forgeSignIn`) at once, the button opening it again once closed | the desktop app hands a new tab to the system browser, which reaches the front on 127.0.0.1; on a phone the scheme brings k7 back by itself, where a loopback page would leave the person in the browser (Android) or in a sheet only Done closes (iOS); a popup opened after the call is blocked in a browser, so the person presses the button there, while iOS's sheet needs no gesture |
| with the built-in client the return is the loopback root on the phones too, since that client takes no app scheme: the Android app leaves the person in the browser on k7's "Signed in" page, and iOS's sheet shows it until Done | the scheme needs a client registered on the server; the page's poll ends the sign-in either way, and a closed sheet is not a failure (`ForgejoSignIn.tsx`) |
| a server is named by its host (`git.example:3000`) everywhere, and a dropped sign-in (`forgejo-signout`) reads "Sign in again" in its section | the routes name every Forgejo "Forgejo", which tells two servers apart nowhere; the front drops the token itself, so the page remembers the refusal it met |
| Remove asks in the page and says the uploaded key stays on the server, and, where `synced`, that the server and its sign-in go from the other Apple devices too | the key is this device's git access and other workspaces may use it, as for GitHub |
| Connect and Clone show one picker per signed-in account (GitHub with `repo`, each signed-in server) and one "Another host…"; the picker is `ForgePicker` over `/git/forges/<id>/repos` for every account | a picker per forge would duplicate the list, the filter and New repository, which differ in a route only |
| a taken name on a server is "A repository named … already exists on <server>" | the server answers 409 `taken`, while GitHub's refusal is its own sentence |
| the dialog shows the device's public key in a read-only box with a Copy button, and one line on where to add it (a deploy key, or the account's SSH keys) | the person's one step on the host; the key is the same for every workspace, so it is made by the device on the first open of the dialog |
| on a Mac that kept its old key beside the Apple devices' shared one (`oldKey` in `GET /git/key`), the box adds one sentence under the key, naming the hosts that took only the old key ("add the shared key above to them"), and "Forget this Mac's old key", which asks in the page before `POST /git/forget-old-key` (`OldKey.tsx`) | the shared key is the user's choice for every Apple device, and a host the person has not given it yet still works on the old key until then; only the person knows when every host has it, and forgetting deletes the old key alone |
| Copy tries the clipboard API, then selects the box and runs `execCommand("copy")`; a failure leaves the key selected and says to copy it by hand | a webview may refuse the async API; the selection is the way every webview lets a person copy (`copyText.ts`) |
| the first call carries no `hostKey`; a 409 `unknown-host` shows the fingerprint and asks, and the call is made again with `hostKey` once the person confirmed it | trust on first use is the person's decision, and nothing was sent to a server nobody vouched for |
| a confirmed fingerprint belongs to the address it was shown for: editing it asks again | a fingerprint carried to another server would trust a key nobody looked at |
| a 409 `host-key-changed` is a warning with both fingerprints and no button to go on; its one way on is "Forget the old key", after which the next call is a first contact | a reinstalled server and a machine on the path look alike, and the dialog cannot tell them apart for the person |
| a host without large-file storage is said after a connection by a dialog, and a push to it shows the server's sentence in the bar | the person can still read and commit; only the push is refused |
| the page tells the server it is in front (`focus`) with each state poll while the tab is visible, and away when it hides (`focusBeat.ts`) | the fetch runs at open, every 5 minutes in front, and when the page returns; it never runs for a tab nobody looks at |
| the demo workspace (`Examples`) offers no "Connect to git…", and the connect route refuses it | the demos are put back as shipped at each start, so a history there fights the reset, and a push would send the demos into the person's repository |
| the workspace menu reads the state once when it opens; connected, it says "Connected to host/repo" (host and repository only) and offers "Change remote…" in place of "Connect to git…" | a plain Connect over a connected workspace would read as a second repository; the same dialog re-points `origin` |
| a connect ends with a toast naming the workspace and the remote, and announces on `gitBus` | the person must see where they clicked that it worked, and every other reader of that workspace (the home row) reads again at once |
| a workspace's home row carries a badge: the branch, the bar's counts and Commit, Push and Pull, read once at mount and on an announcement, never polled | the bar's pieces (`BarBody` in its `row` form) keep the rules in one place, and a home page of many workspaces must not poll each of them |
| a card asks the host for one fetch when the home page opens and reads its state again a few seconds later; its "Up to date" line says how long ago the last fetch ran | a card that read once would call a workspace up to date on the strength of a fetch days old |
| a card's pull bar says "Pulling {branch} from {remote}" | the pull does not merge until it has fetched, and the remote is the one the state names, never a fixed word |
| the home page's "On your other devices" lists the workspaces added elsewhere that have a git remote and are not here, each with a Clone; one with no remote is not shown | a workspace needs a git remote to travel, and the clone is the clone dialog opened with the address and the name filled in, so the host-key question and the name's collision check are the ones the person knows |
| the list is read when the page opens and every 20 s while it is visible, a failed read keeps the last answer, and a cloned entry hides at once (`roamState.ts`) | the section is a convenience and never a gate; the person must not see the entry they just cloned for the length of a poll |
| History has two lists: Edits (the local history, as it is) and Commits (the log, older pages on demand) | an edit is a step of this device; a commit is what was named and shared |

## Where each screen is

| screen | place |
|---|---|
| Connect to git | the workspace's menu, "Connect to git…" |
| Clone from git | the home page's header, beside "New workspace" |
| On your other devices | the home page, under the header, only where the host has a list (iOS) |
| the bar | above the project bar in the editor, and above a workspace's tree on the home page |
| Commit & Push and the Conflict screen | dialogs opened through `gitScreens.tsx` (`openCommitAndPush`, `openConflict`), by the header and the workspace card |
| Commits | the History panel's second list, shown when the workspace is under git |
| the commit author | settings, General (an empty field is prefilled, with its source under it; see below) |
| Sign in with GitHub, the account, Manage keys and Sign out | settings, Services |
| the Forgejo servers: Add, Sign in, Sign in again, Remove | settings, Services, under GitHub |

## The commit author

An empty name or email is prefilled, each field on its own, from the first source that has it: the signed-in forge account (GitHub first, then the Forgejo servers in list order), the desktop's global git config, then the system account's full name (a Mac or a Linux desktop; a name only). A typed field is never replaced, and the prefill is never stored: the page sends a field still showing its suggestion as empty, so it keeps following its source, and a commit uses the suggestion as if typed.

- The iPad and iPhone have no OS source, which is why the forge account comes first: a signed-in account is the one thing every device has.
- A GitHub account that hides its email answers GitHub's own commit address (`<id>+<login>@users.noreply.github.com`), so a private email stays private and the commits still link to the account.
- The identity stays per device. What a forge said of the account is cached in a per-device file, never in the keychain entry iCloud syncs, and the email goes nowhere it did not already go.

## Tests

`gitState.test.ts` holds the rules of the bar as data; `connectState.test.ts` (the address, the trust, the refused web addresses), `copyText.test.ts` (the clipboard and its fallback), `mergeState.test.ts`, `commitState.test.ts` and
`logState.test.ts` hold the reducers and their refusals; `roamState.test.ts` and `OtherDevices.test.tsx` the list's reducer and the section; `gitLock.test.ts` the gate that keeps the editors still, with its wiring
into `App.tsx`; `GitBar.test.tsx` renders the bar and the cards; `githubState.test.ts` holds the device-flow screen's states and the picker's order, filter and dates, `ForgeWays.test.tsx` the pickers' place in the dialogs, `forgejoState.test.ts` the add and sign-in screens' states, `forgeOpener.test.ts` the sign-in's way per host, `ForgejoSection.test.tsx` the servers' section and the check's facts, `GitHubSection.test.tsx` the Services section's states, `identitySource.test.ts` the source line under a prefilled author. The functional specs are `e2e/specs/app/git-sync.spec.ts` and, per forge, `github-signin.spec.ts` and `forgejo-signin.spec.ts`.
